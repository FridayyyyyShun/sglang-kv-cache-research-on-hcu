# M2 共享引用、host锁与驱逐保护

1. 建立共享前缀，等写回完成，压L1至共享前缀只在L2。
2. 发3个共享前缀、不同尾部的长生成请求。
3. 飞行中取快照：要求每rank至少两个running请求，且存在device_lock>=2的共享节点。单个锁>0不等于共享并发。
4. 要求这组请求确实有host来源；结束后每rankprotected和非root双层锁归零。
5. storage配置下flush本地树后重复，要求这组请求确实有storage来源。
6. 检查host锁获取/释放事件；任何evict/evict_host都不能回收调用前仍锁住的页。

异步D2H/H2D/storage提交和完成分别保留。自然压力未碰到host驱逐与host锁竞争时单列NOT_EXERCISED，不把没有竞争当作竞争安全已通过。
