# M5 分层miss归因

建立四类明确操作：新token命名空间的cold；查询上限/页尾排除；L1容量驱逐但L2补回；flush L1/L2后由L3补回（无L3则应真的miss）。

每请求验证cached_tokens=device+host+storage，保存操作前状态、details和相关事件。L1 miss而host>0不是整个分层缓存miss；同理L1/L2为空但storage>0是L3恢复。

salt A建立后，salt B查询同token：本地device/host命中必须0。现场L3 key为token-only，storage可能复用；这种行为单独记录，不能套用进程内salt隔离断言。

脚本记录已构造场景的归因证据，不声称对任意生产trace做逐页全知归因。页面尾部与查询上限排除按实际Q记录。
