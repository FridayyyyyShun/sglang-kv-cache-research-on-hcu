# M6 ready、真实取消与双层释放

1. flush至空树，取逐rank设备available和每个host/DSA辅助poolavailable作为基线。
2. 每cycle先用全新token取得cached=0的8token冷参考，再将同前缀写入/压到L2。
3. 长生成收到首token后取飞行快照，对自己rid发abort_all=false的定向abort。
4. 必须收到abort终止原因且生成数小于max_new。正常生成已完成而取消窗口未命中，记NOT_EXERCISED；HTTP 200本身不证明取消成功。
5. 等所有请求、write/load/prefetch/backup字典、确认队列与host页释放队列排空；非root双层锁归零，树token账本自洽。
6. 重发8token与建立缓存前的真实零命中参考比较。不同则FAIL并保留输出，不依据锁账本正常就排除语义错误。
7. flush后每rank设备池和所有host/辅助池available必须回到基线，连续cycle不能累计泄漏。
8. storage配置另试L3预取期间定向取消：需要同时捕获该rid预取提交和实际ongoing_prefetch窗口。没碰到窗口就标未覆盖，不用首token后的取消冒充预取中取消。

输出一致不等于KV张量逐字节相同；本项证明的是观测到的请求语义和回收契约。L3文件会保留，文件仍存在不算主机/设备页泄漏。
