# M4 多轮、未完成请求与恢复

1. 用原生output_ids构造4轮真实历史，每轮追加本轮输出和2P新用户token，不做字符串分词近似。
2. 上轮max_new=1时，上轮输入KV已计算，那个新采样token尚未计算KV。下一轮的预期复用为floor(上轮输入长度/P)×P。
3. 等每轮完成后取快照，压最后历史到L2再恢复，要求host来源。
4. flush后逐rank确认树/本地槽空；host配置重发应0命中，storage配置重发应从L3恢复。
5. 再启动一个长生成请求，首token后并发提交重叠前缀探测。只有逐rank证明cache_unfinished_req先于探测match、cache_finished_req晚于探测，且探测正命中，才算未完成请求增量复用通过。

若源请求先完成或没有走增量发布路径，该子项记NOT_EXERCISED。等待几秒后看到命中本身不构成未完成复用证据。
